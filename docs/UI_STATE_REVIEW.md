# RecTheWord 界面功能与状态切换设计审查报告

> 触发：用户连续两次发现界面问题（浮窗字幕丢失 / 延迟不显示 / 状态栏卡死 / 无停止键 /
> 翻译不可见）。本报告系统梳理**每个 UI 组件应有的状态集合、状态如何被驱动、
> 当前实现的差距**，给出结论与修复清单。

## 0. 结论摘要

| 维度 | 评价 | 说明 |
|---|---|---|
| 数据流架构 | ✅ 合理 | EventBus 单向驱动，UI 纯渲染，进程隔离清晰 |
| 状态建模 | ⚠️ 部分缺口 | 有 StatusMachine（加载态），但**录音生命周期态**（idle/录音/暂停/停止）此前未建模，导致 UI 元素无人驱动 |
| 浮窗完整性 | ❌ 已修 | 延迟、状态栏、译文回填此前全是空壳 |
| 控制闭环 | ❌ 已修 | 暂停/停止按钮此前未接线，现已接 pipeline |
| 翻译可见性 | ⚠️ 已修 | mock 回显原文造成「像没翻译」，已改为明显不同的【译】前缀 |

**根本教训**：之前只验证了「数据能到 UI」（asr/trans 事件有值），但没验证
「每个 UI 元素的状态都被某个事件驱动」——这是本次一系列问题的共同根源。

## 1. 全局状态机（应有 vs 已实现）

一次运行的完整生命周期：

```
idle ──启动──► loading(env/vad/asr/api) ──就绪──► recording
                                                    │
                          ┌─────────────────────────┤
                          ▼                         ▼
                       paused ◄──────► recording
                          │
                          ▼ 停止
                       stopped（会话归档，零后台计算）
```

| 状态 | 驱动源 | 应影响的 UI 元素 | 修复前 | 修复后 |
|---|---|---|---|---|
| loading | StatusMachine(status) | splash 进度条、toast | ✅ 已有 | ✅ |
| recording | pipeline 启动 | 顶栏「● 录音中」、dock 计时、浮窗状态栏 | ⚠️ 顶栏有，浮窗状态栏卡在「等待语音…」 | ✅ 浮窗显示「录音中·等待语音…」 |
| paused | `pipeline.pause()` | dock ❚❚→▶、浮窗状态栏、（可选）顶栏 | ❌ 无暂停语义 | ✅ 浮窗「已暂停」 |
| stopped | `pipeline.stop()` | dock 按钮禁用、浮窗状态栏、顶栏 | ❌ 无停止键 | ✅ 浮窗「已停止」、按钮禁用 |
| api_degraded | trans_err/asr_err | toast、对应行 ⚠ | ✅ 已有 | ✅ |

## 3. 发现的问题与根因（按发现顺序）

1. **浮窗字幕丢失**：`overlay.py` + `main_window.py` 各一处 `removeItemAt`（PySide6
   应为 `takeAt`）→ 超限裁剪时抛 `AttributeError`，`EventBus.pump` 不捕异常 → 中断
   整个 "asr" 派发链（主窗口先订阅已拿到，浮窗后订阅永收不到）。**已修。**
2. **浮窗延迟不显示**：`tick_clock` 硬编码 `延迟 -`，从未有人写入真实延迟。**已修**
   （`set_latency` 由 `on_asr` 的 `t_first_ms` 驱动）。
3. **浮窗状态栏卡死「等待语音…」**：`set_status` 存在但无人调用，录音生命周期态未建模。
   **已修**（`set_running` 三态）。
4. **无停止键**：dock 只有暂停 toggle，且都未接 pipeline。**已修**（新增 ■ 停止 +
   暂停/停止均接线，停止后按钮禁用）。
5. **翻译「看不见」**：mock 回显原文（`[tgt] 原文前30字`），视觉上像没翻译；且浮窗
   译文回填是空壳。**已修**（mock 改【译】前缀明显改写 + 浮窗译文接通）。

## 4. 仍存在的缺口（诚实披露，待办）

| 缺口 | 影响 | 建议 |
|---|---|---|
| dock「说话人」「磁盘」显示静态占位 | 用户看不到真实值 | 接 `stats` / 会话大小 |
| 「导出记录」「生成纪要」按钮未接线 | 点了没反应 | 接 `SessionStore.export_markdown` / `generate_minutes` |
| 顶栏「录音中」未随暂停/停止变色 | 状态感知弱 | 接三态文案 + 颜色 |
| 暂停时 ASR 队列未显式排空 | 恢复可能有短暂积压 | 可在 resume 前排空 seg_q |
| 浮窗与主窗口字幕是两套独立渲染 | 重复计算 | 可统一为单一数据源（当前可接受） |
| 真实 WASAPI 采集/环回/设备切换 | 本机无法验证 | **必须在用户 Windows 笔记本验收** |

## 5. 设计合理性总评

- **数据流（EventBus 单向 + 进程隔离）**：✅ 设计优秀，是整套 UI 能解耦的基础。
- **状态建模**：⚠️ 加载态（StatusMachine）完备，但**运行时生命周期态**此前缺失——
  这是本次问题的共性根因。已补 `pause/resume/stop` + UI 三态联动。
- **降级路径**：✅ API 不可用时显式报错（trans_err/asr_err），符合「不静默失败」约束。
- **等待态机制**：✅ 任何异步等待都经 StatusMachine 广播，符合「显式告知用户」约束。
- **可测试性**：✅ replay 注入源使非 Windows 环境能端到端验证整条链路。

**一句话**：骨架（数据流 + 进程隔离 + 等待态）设计扎实；短板在「运行时状态没有一等
公民地位」，导致一批 UI 元素成了没人驱动的静态壳。本次已把录音生命周期态补成一等
公民（pause/resume/stop + 三态 UI 联动），并逐一接通了浮窗/控制/翻译的驱动源。
